# Dossier schema (fill exactly; no extra sections)
Per exemplar (budget 200-350 words, dense):
1. Header: exemplar, org, years, key people; why it is in (iconic for QA? negative? control?).
2. Layers, outermost to innermost: table | layer | what it catches | who/what runs it | when in the lifecycle |
3. Seed questions, one line each or "not addressed":
 Q1 What is tested and when (scope, risk-based choice)?
 Q2 Who tests (devs, testers, real users, automation/agents), and what can each uniquely catch?
 Q3 How is a finding reported and triaged (severity scale, ownership)?
 Q4 How is real exposure rehearsed (dry run, staging, dogfood, soft launch, beta)?
 Q5 How is it broken on purpose (crash, chaos, stress, adversarial, red team)?
 Q6 How is "ready to ship" decided (gates, exit criteria, go/no-go)?
 Q7 How is it watched after release (monitoring, telemetry, feedback channels)?
 Q8 How is learning done after failure (post-mortem form, blamelessness, action items closed)?
 Q9 How does learning flow back into the system (checklists, regression tests, standards)?
 Q10 Open: anything else this exemplar solves that the list misses.
4. 1-3 most successful practices: exact mechanics; evidence grade A (measured, controlled/large data), B (credible case data, practitioner report with numbers), C (anecdote, reputation); driver (why it works, named effect); source URL.
5. Known failures/criticism with source.
6. 1-2 verbatim intent quotes with source.
End of file: Cluster patterns (5-10 bullets: candidate invariants + recurring best practices).
Rules: cite every fact with URL; mark *Judgment* separately; no synthesis across clusters; web_search/web_fetch only; no browser.
