# Canonical Commercial System — Activation Runbook

## One ledger, three operating views

1. ICP Prospector discovers and qualifies people.
2. Outreach Radar reconciles LinkedIn history, drafts and sends.
3. Relationship Hub unifies LinkedIn and Gmail, then governs follow-up and commercial expansion.

Canonical journey:

source → connection → reply → call → offer → payment → delivery → expansion

## Go-live gates

- Exact live tool names recorded.
- Connector response shapes observed, not assumed.
- One-person import path verified across all three tools.
- No duplicate person after cross-channel merge.
- No real message or connection request sent during testing.
- Backups saved after first substantial sync.
- The final exported ledger contains source, reply, call, offer, payment, delivery and expansion fields.

## Weekly commercial ritual

1. Sync Relationship Hub.
2. Work Need follow-up oldest-first.
3. Record calls, offers, payments, delivery and expansion on the same person.
4. Export the ledger backup.
5. Feed downstream outcomes back into Tool 1 term performance.
6. Judge ICPs by replies, calls and payments, not search volume.

## Closing the learning loop

After the weekly Relationship Hub export, restore that canonical ledger file into ICP Prospector. Tool 1 reads the envelope outcomes and attaches replies, calls, offers, payments and cash to the originating ICP/search term. This is the return wire: downstream commercial truth changes upstream prospecting intelligence.

All three exports now use:

- schema: evolver-commercial-ledger
- version: 1
- records: the same people, progressively enriched
- outcomes: Tool 3 aggregates results by original ICP and search term
